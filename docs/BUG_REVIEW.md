# GalleryBrowser (Python) bug review

Static review of the PyQt6 implementation on `main`. Each item: location, severity, defect, trigger, fix. All are addressed by design in the Rust rewrite on branch `rust-rewrite`.


## Core & workers

**Scope note:** The working-tree diff for these files contains only executable-bit changes (`100644 → 100755`), not implementation changes. There are **no patch-introduced findings**. The following are existing implementation defects identified for the broader audit/rewrite. Analysis was read-only; no application or tests were run.

1. **`src/gallerybrowser/core/file_manager.py:358` — high — Renaming can silently overwrite an existing file.** The single-file rename UI passes the requested destination without checking whether it exists (`views/main_window.py:558–559`). If `gio move` rejects an existing destination, `_do_rename()` falls through to `shutil.move()`, which can overwrite that file on Linux. Undo restores the renamed source but cannot recover the overwritten destination. **Fix:** reject destination collisions before invoking either backend, or implement an explicit overwrite operation with recoverable destination contents. Do not turn a backend refusal into an unchecked overwrite.

2. **`src/gallerybrowser/core/file_manager.py:268–273` — high — File operations block the GUI thread.** Copy, move, trash, permanent deletion, and rename run synchronously; subprocess calls have no timeout, and directory operations use blocking `shutil` calls. Paste/drop/rename/delete handlers invoke these methods directly (`views/main_window.py:517–519`, `542`, `559`, `859–861`). Copying a large file or operating on a stalled NAS freezes the entire interface for the operation’s duration. **Fix:** execute filesystem/subprocess work outside the GUI thread and deliver completion/errors back through signals; keep history updates serialized.

3. **`src/gallerybrowser/workers/thumbnail_worker.py:60–63` — medium — A timed-out stop strands the next folder’s thumbnail queue.** A thumbnail operation can exceed the five-second wait: its ffprobe and ffmpeg timeouts are 15 and 30 seconds. `FilePane.set_files()` proceeds after `stop()`, replaces the queue contents, and calls `generate_thumbnails()`. Because the old worker is still running, the caller does not restart it. When its current operation finishes, the still-set stop event makes it exit, leaving the new thumbnails queued without a worker. **Fix:** coordinate restart with actual worker termination, or use a persistent worker with generation-based cancellation rather than stop/restart per folder.

4. **`src/gallerybrowser/workers/frame_loader.py:64–66` — high — Replacing a sequence can retain an out-of-range loading center.** `set_sequence()` replaces the paths and generation but does not reset `_center` or clear a previously pending event. If the worker consumes that event after a long sequence is replaced by a shorter one, but before `SequencePlayer` calls `load_around(0)`, it snapshots the old center with the new paths. `_build_load_order()` unconditionally includes that center, and `paths[idx]` at line 167 raises an uncaught `IndexError`. **Fix:** reset/clamp the center and invalidate pending work atomically with sequence replacement; also validate the center when constructing a batch.

5. **`src/gallerybrowser/core/sequence_player.py:272–278` — medium — A delayed retry can display a frame from the previous sequence.** The retry checks only the numerical index, not the active sequence/path. Meanwhile, `FrameLoader.run()` checks its generation before decoding but not before inserting the decoded image (`workers/frame_loader.py:171–174`). Switching sequences while frame zero is decoding can therefore repopulate the cleared cache with the old frame; an already scheduled 50-ms retry emits it as frame zero of the new sequence. Both preview consumers display the image unconditionally. **Fix:** reject stale decode completions and bind retries to a sequence generation or verify the current indexed path.

6. **`src/gallerybrowser/core/image_io.py:48–52` — medium — Failed buffering leaks partial files in `/dev/shm`.** If writing a buffered EXR fails, particularly with `ENOSPC`, the exception handler returns the original path with `needs_cleanup=False`. The partially written `gb_<id>.<ext>` is never removed, including by the caller’s `finally` block. This can leave shared memory full and cause subsequent buffering attempts to fail repeatedly. **Fix:** unlink any partially created temporary file before falling back to the original path.

7. **`src/gallerybrowser/core/sequence_player.py:194` — medium — Sparse sequences display incorrect source frame numbers.** File-pane sequence detection retains the actual `fileseq` frame set, including gaps, but passes only ordered paths and `(start, end)` to the player (`views/file_pane.py:1106–1144`). The player computes the displayed number as `start + index`. For frames `1001, 1003`, the second frame is consequently labeled `1002` in both preview modes. **Fix:** pass the ordered source frame numbers alongside their paths and use that mapping for display.

8. **`src/gallerybrowser/core/thumbnail.py:230–232` — medium — The configured disk-cache limit is never enforced.** Thumbnails accumulate under size-specific directories; source modifications create additional hashes, and no eviction removes previous versions. `max_cache_mb`, default `1000`, is exposed and saved by the settings dialog but has no cache-side consumer. Repeated browsing or changing rendered sequences can grow the cache beyond the selected limit indefinitely. **Fix:** enforce a disk-cache budget and evict entries across the thumbnail-size directories.

9. **`src/gallerybrowser/core/ram_cache.py:65–71` — medium — An individual oversized frame bypasses the RAM budget.** `put()` evicts until the cache is empty, then inserts the image regardless of whether that image alone exceeds `_max_bytes`. This defeats a reduced RAM limit when opening sufficiently large frames, even though `set_max_bytes()` otherwise enforces the limit. **Fix:** explicitly handle oversized entries without caching them above the budget; preserve a separate delivery path for displaying an uncached current frame.


## Database, config, app

These are current-source audit findings, not patch-introduced findings: the working diff contains no changes to the assigned Python files. No application, tests, or builds were run.

1. **`src/gallerybrowser/app.py:70–80` — medium — Stop the thumbnail worker during application shutdown.** The window closes the preview and information panes but never calls `self.main_window.file_pane.cleanup()`. That method exists at `views/file_pane.py:1739` and stops the thumbnail worker. Neither the child `MainWindow.closeEvent()` nor the entrypoint’s `aboutToQuit` callback stops it either. **Trigger:** close the application while a sufficiently large thumbnail queue is still processing. The worker remains active during shutdown instead of being cancelled and joined. **Fix:** include the file pane in coordinated shutdown, and ensure its worker has finished before destroying its owner or the application.

2. **`src/gallerybrowser/database/manager.py:486–492` — medium — Include unindexed filesystem files in the folder’s “Unrated” results.** `get_unrated_files()` only returns existing `files` rows without a rating. Its consumer, `MainWindow._apply_library_filters_to_folder()` (`views/main_window.py:702–707`), intersects that result with the filesystem scan. Scanning does not insert database records; records are created by assigning tags, adding collection membership, or rating files. **Trigger:** open a previously unannotated folder and select “Unrated.” Its unrated files disappear because they have no database rows. **Fix:** in folder scope, exclude paths that have ratings from the scanned files, rather than requiring membership in the database’s unrated subse…

3. **`src/gallerybrowser/database/models.py:60–61` — medium — Preserve UTC semantics when reading stored modification times.** The manager writes UTC-aware datetimes (`manager.py:143–144`, also the tag/collection creation paths), but SQLite’s SQLAlchemy `DateTime` representation omits timezone information. The consuming `MainWindow._file_record_to_view_item()` calls the resulting naive datetime’s `.timestamp()` (`views/main_window.py:714`), interpreting UTC clock fields as local time. **Trigger:** tag, collect, or rate a file on a machine with a non-UTC timezone, then display it through library results. Its list-view modification time differs from its folder-view time by the timezone offset. **Fix:** store epoch timestamps, or consistently restore UTC timezo…

4. **`src/gallerybrowser/config.py:27–35` — medium — Check actual writability before accepting a state directory.** `_ensure_writable_dir()` only calls `mkdir(exist_ok=True)`. An existing, readable but non-writable directory passes that operation, so the advertised fallback is never selected. **Trigger:** an existing application cache directory is owned by another user or has write permission removed. Startup subsequently fails when creating its lock directory or database, despite a writable repository-local fallback being available. The same issue affects configuration saves. **Fix:** verify the required write operation inside the helper, or handle creation/write failure at the call site and consistently select the fallback.

5. **`src/gallerybrowser/resources/styles.py:802–811` — medium — Use a per-user directory for generated theme assets.** Every user writes the same two files under `${TMPDIR:-/tmp}/gallerybrowser_arrows`. **Trigger:** one Linux user launches the app with the usual `022` umask, creating a directory and SVGs that another user cannot overwrite; the second user then launches it using the same system temporary directory. `apply_theme()` raises an uncaught `PermissionError` before showing the window. **Fix:** use packaged SVG resources, a user-specific cache directory, or a securely created private temporary directory.

6. **`src/gallerybrowser/app.py:67–68` — low — Connect the About menu action.** The enabled Help → About action has no `triggered` connection or other handler. **Trigger:** select About; nothing happens. **Fix:** connect it to an About dialog displaying the existing application/version/author/license information.


## Main window & side panels

**Scope:** The current diff for these files contains only executable-bit changes. The issues below are **existing implementation defects found during the requested whole-code audit**, not regressions introduced by that diff. No application, tests, or builds were run.

1. **`src/gallerybrowser/views/main_window.py:175–180` — medium — “New Folder” is completely unwired.**  
   The toolbar advertises a New Folder action and `Ctrl+Shift+N`, but neither `connect_actions()` nor the application wrapper connects it to a handler. Clicking it or using its shortcut does nothing. **Fix:** connect it to folder-name entry, directory creation in the active folder, error handling, and a refresh.

2. **`src/gallerybrowser/views/main_window.py:559–560` — high — Renaming or moving files disconnects their stored metadata.**  
   Rename, cut/paste, batch rename, and tree-drop moves only call `FileManager`; that class changes filesystem paths without updating database records. Tags, collections, and ratings are retrieved by the old `File.path`, so renaming a tagged/rated file makes those associations disappear from the visible file. Library results omit the old record because its path no longer exists. Reusing the original filename can instead associate the old metadata with an unrelated replacement file. **Fix:** after each successful move/rename, update the existing record’s path, filename, and folder while preserving its ID and relationships; reconcile deletion similarly.

3. **`src/gallerybrowser/views/main_window.py:896–897` — medium — Toggling sequence collapse bypasses active metadata filters.**  
   With a folder-scoped tag, collection, or rating filter active, changing Collapse Sequences calls `FilePane.set_collapse_sequences()`. That method calls `set_folder()` directly, rescanning and displaying the entire folder without `MainWindow._apply_library_filters_to_folder()`. The selected filter and status description remain active even though unrelated files are displayed. **Fix:** make the toggle update the collapse flag, then rebuild through `MainWindow.refresh_view()` so the same query pipeline always runs.

4. **`src/gallerybrowser/views/main_window.py:681–687` — medium — “Unrated” excludes files that have never entered the database.**  
   Folder scanning does not register every discovered file. The Unrated filter nevertheless restricts the scan to `db.get_unrated_files()`, which queries only existing `File` rows. Opening a previously unseen folder and selecting Unrated therefore hides its genuinely unrated files, often producing an empty result. **Fix:** in folder scope, treat absent database records as unrated—for example, subtract rated paths from the scanned paths. Retain database-only semantics for library scope.

5. **`src/gallerybrowser/views/main_window.py:541–542` — high — File operations on a collapsed sequence affect only its representative frame.**  
   `FilePane.scan_folder()` represents a sequence with the middle frame in `path` and the full frame list in `sequence_files`. `get_selected_files()` returns only those representative paths. Delete, copy, cut, and rename handlers consume them as ordinary files. Selecting and copying a sequence consequently copies one frame; deleting it removes one frame while leaving the rest behind. **Fix:** resolve selected sequence rows to their complete frame sets before file operations; use sequence-aware naming for rename rather than renaming a single representative.

6. **`src/gallerybrowser/views/main_window.py:869–884` — medium — Backspace navigation is routed into preview loading.**  
   `FilePane.keyPressEvent()` emits the parent directory through `file_selected` when Backspace is pressed (`file_pane.py:1526–1534`). The connected handler here always treats its argument as media and sends it to PreviewPane and InfoPane. The browser stays in the same folder and the preview receives a directory instead. **Fix:** give FilePane a separate folder-navigation signal and connect it to `on_folder_selected()`.

7. **`src/gallerybrowser/views/settings_dialog.py:142–145` — medium — Four exposed preferences have no runtime consumers.**  
   `show_hidden`, `video_preview`, `thumbnail_threads`, and `max_cache_mb` are saved and restored by the dialog but never consumed elsewhere in `src/gallerybrowser`. MainWindow applies only thumbnail size and the sequence RAM budget. Consequently, disabling video preview does not disable it; changing worker count or cache limit has no effect; hidden directories remain excluded from the tree regardless of the checkbox, while hidden supported files are not excluded by the file scanner. **Fix:** implement each preference in its actual consumer and apply it consistently, or remove the nonfunctional control.

8. **`src/gallerybrowser/views/main_window.py:516–519` — high — File transfers block the GUI thread for their full duration.**  
   Paste and tree-drop handlers call `FileManager.copy()`/`move()` synchronously. Those methods execute blocking `subprocess.run()` calls and `shutil` copies/moves. A large video transfer or cross-filesystem move therefore prevents event processing until the operation finishes, freezing navigation, repainting, and playback controls. **Fix:** execute filesystem operations in a worker and return progress/completion/error notifications to GUI-thread handlers; refresh after completion.

9. **`src/gallerybrowser/views/tags_panel.py:56`, `collections_panel.py:54`, `tree_pane.py:153` — medium — Keyboard selection changes the highlighted item without changing the active source/filter.**  
   All three navigators connect only `itemClicked`. Moving through their rows with the keyboard does not emit the application’s selection signal, and Enter is not connected to activation. The visible selected tag, collection, or folder can therefore disagree with the displayed results. **Fix:** connect explicit keyboard activation or current-selection changes, with signal blocking during programmatic synchronization to avoid feedback loops.


## File pane & batch rename

Paths below are relative to `src/gallerybrowser/views/` unless otherwise noted. The available diff contains only executable-bit changes for these files; these are findings in the current implementation, not claims that the mode changes introduced them. No app, tests, or builds were run.

1. **`batch_rename_dialog.py:704-714` — high — Batch rename can overwrite existing files, including another input file.** Validation only checks whether two *output names* match; it does not check existing destinations or dependencies between renames. For example, select `1.jpg` and `2.jpg`, enable replacement numbering with start `2` and padding `1`: the preview accepts `2.jpg` and `3.jpg`. `main_window.py:1164-1166` executes these sequentially, and `core/file_manager.py:339-359` falls back to `shutil.move`, which can overwrite `2.jpg` before that source is processed. **Fix:** validate complete destination paths, reject collisions with unrelated files, and execute dependent renames through unique temporary paths before committing final names.

2. **`file_pane.py:1125-1144,1624-1626` — high — File operations on a collapsed sequence affect only its representative frame.** A sequence’s selection identity is its middle-frame path. Context menus and drag-and-drop export that path, while the actual frame list remains in `sequence_files`. The consumers in `main_window.py:481-560,1151-1170` do not expand it: deleting a 100-frame sequence trashes one middle frame; cutting, copying, or renaming similarly operates on only one frame. **Fix:** preserve sequence identity for preview/selection, but expand operation targets to all sequence members; provide sequence-aware renaming rather than renaming only the representative.

3. **`file_pane.py:1382-1396` — medium — Shift-click can index past the filtered file list.** Select an item near the end of a folder, narrow the search/type filter to a smaller list, then Shift-click a remaining item. `display_files()` retains `last_selected_index`, and the range loop uses the old index against the shorter list, raising `IndexError`. **Fix:** reset or recompute the selection anchor whenever the displayed list changes, and bound range selection to the current list.

4. **`file_pane.py:1309-1315,1615-1637` — medium — List-view selection and the operation selection diverge.** Qt first updates its extended row selection, but `itemClicked` then calls `on_file_clicked(file_path)` without modifiers. That takes the normal-click branch and replaces `selected_files` with only the clicked path, even while several rows remain highlighted. Additionally, `clear_selection()` never clears table selection, and `set_selection()` cannot restore list selections because it only checks `file_widgets`, which list mode empties. **Fix:** make the table’s selection model authoritative in list mode; use clicks only for preview updates, and implement clearing/restoration through that model.

5. **`file_pane.py:1236-1260,1427-1430,1639-1654` — medium — Searching, sorting, and filtering discard loaded thumbnails without loading replacements.** Every grid refresh destroys its cards and constructs placeholders. These setters call `display_files()` but not `generate_thumbnails()`, and new cards do not retrieve cached images themselves. Once the previous worker queue has drained, a search or sort leaves the rebuilt grid showing placeholders. **Fix:** retain/reposition existing cards or request cached/generated thumbnails after every grid rebuild.

6. **`file_pane.py:1241-1260` — medium — Rebuilding the grid loses selection highlighting but retains actionable selections.** New cards always start unselected, while `selected_files` is unchanged. After a sort, selected items appear deselected but still participate in toolbar/context-menu operations. Filtering can leave hidden paths selected: select A and B, filter to B, then right-click B; the menu still operates on A and B. **Fix:** explicitly reconcile selection against the displayed source and apply retained selection state to every rebuilt card.

7. **`file_pane.py:1002-1008` — medium — Toggling sequence collapsing bypasses active library filters.** In folder scope, `MainWindow.refresh_view()` applies `_apply_library_filters_to_folder()` before calling `set_files()` (`main_window.py:588-596`). The collapse toggle instead calls `set_folder()` directly, rescanning and displaying the entire folder without those filters while the tag/collection/rating query remains active. **Fix:** change the collapse setting and request a refresh through the same query/filter pipeline.

8. **`file_pane.py:1441-1451` — medium — Thumbnail resizing does not update library results.** Library results intentionally use `set_files(..., current_folder="")` (`main_window.py:598-600`). The resize method requires a nonempty `current_folder`, so changing the slider updates `thumbnail_size` but leaves existing library cards and thumbnails at their previous dimensions. **Fix:** rebuild based on the presence of displayed files, not a folder path.

9. **`file_pane.py:320-322` — medium — The scrub worker creates and transfers `QPixmap` off the GUI thread.** `_seek_loop()` runs in `QThread.run()` and calls `QPixmap.fromImage()` there. This violates the GUI-resource threading contract already respected by `ThumbnailWorker`, which emits `QImage` and creates pixmaps in the GUI callback. **Fix:** emit the copied `QImage` and convert it to `QPixmap` in `_on_scrub_frame()`.

10. **`file_pane.py:309-316` — medium — Scrub frames assume tightly packed RGB rows.** The `QImage` constructor uses `width * 3` as its row stride, although GStreamer RGB buffers can have padded row strides. A video whose RGB row length is not four-byte aligned—for example, width 854—can therefore display shifted/corrupted rows. **Fix:** obtain the negotiated stride through `GstVideo.VideoInfo`/`VideoFrame` and construct or copy the image using that stride.

11. **`file_pane.py:153,648-657` — medium — Ctrl-hover scrubbing cannot decode several advertised video formats.** Every video card starts the same pipeline, but its demuxer is always `qtdemux`, which handles QuickTime/MP4 rather than AVI, Matroska/WebM, MXF, or MPEG containers. Those formats are explicitly accepted by `Config.VIDEO_EXTENSIONS`, so they appear as scrubbable video cards but produce no frames. **Fix:** select the appropriate demuxer or use container discovery/autoplugging while preserving video-only decoding.

12. **`file_pane.py:65-72,476-481` — medium — Leaving a scrubbed thumbnail can block the GUI for two seconds.** `leaveEvent()`/Ctrl-release processing synchronously calls `_destroy_gst_pipeline()`, which calls `worker.stop()` and `wait(2000)` on the GUI thread. Pipeline setup itself can wait five seconds, and the NAS pre-read is blocking; leaving during either operation stalls the interface until the wait expires. The timeout is also not checked before shared worker state is discarded. **Fix:** request cancellation asynchronously, retain the worker until `finished`, and let the worker own pipeline teardown.

13. **`file_pane.py:1526-1534` — medium — Backspace emits the wrong signal for parent-folder navigation.** The handler emits `file_selected(parent_directory)`, but the connected receiver, `main_window.py:869-884`, only updates the preview and information panes. It has no directory-navigation branch, so executing this handler does not navigate upward. **Fix:** introduce a folder-navigation signal connected to the normal folder-navigation handler.

14. **`file_pane.py:1045-1049` — medium — Refreshing a removed or unavailable directory raises an uncaught exception.** The folder scan catches only `PermissionError`. If the current directory is deleted externally, a mount disappears, or the path becomes a regular file, `Path.iterdir()` raises another `OSError` subclass and interrupts the refresh. `MainWindow.refresh_view()` calls this directly. **Fix:** handle directory-listing `OSError`s at the scan boundary and return/report an unavailable-source result.

15. **`batch_rename_dialog.py:709-714` — medium — Duplicate checking incorrectly rejects valid cross-directory renames.** Library selections can contain files from different directories, but `seen_names` is keyed only by basename. Renaming `/A/image.jpg` and `/B/image.jpg` to `IMAGE.jpg` is safe, yet the second row is marked a duplicate and Rename is disabled. **Fix:** check complete destination paths, preserving case-sensitive Linux semantics.

16. **`batch_rename_dialog.py:609-611` — medium — Case-insensitive literal replacement interprets regex replacement escapes.** With Regex disabled but Case sensitive unchecked, replacement text is passed directly to `re.sub`. Thus literal `\n` becomes a newline, while a literal `\1` can raise `re.error` and silently leave the filename unchanged. These are valid literal filename characters on Linux and behave differently with Case sensitive enabled. **Fix:** use a replacement callback returning the entered text unchanged for the non-regex branch.


## Preview & info panes

The working-tree diff for these files contains only executable-bit changes. The following are **existing-code defects found during the requested audit**, not regressions attributable to that diff. Inspection was read-only; no application or tests were run.

1. **`src/gallerybrowser/views/preview_pane.py:806` — medium — Stop permanently disables playback of the selected video.**  
   The Stop button connects directly to `stop()` at line 372. That method destroys the pipeline and sets `_pipeline = None`, whereas `play()` returns immediately without a pipeline. **Trigger:** load a video, press Stop, then Play; playback cannot resume without selecting/loading the video again. **Fix:** separate user-facing stop/reset from pipeline teardown; retain a paused pipeline positioned at the beginning, or explicitly reload the current file when playback resumes.

2. **`src/gallerybrowser/views/preview_pane.py:644` — medium — Loading another video silently discards mute and volume settings.**  
   Each new audio branch creates a fresh `volume` element without applying `_is_muted` or the volume slider’s value. The controls and `_is_muted` survive the file change. **Trigger:** mute a video or set volume to zero, then select another video with audio; the new pipeline uses default unmuted/full-volume settings while the UI still indicates the previous setting. Loading briefly enters PLAYING, so sound can occur during selection itself. **Fix:** apply the current mute and volume values to every newly created audio branch before synchronizing its state with the pipeline.

3. **`src/gallerybrowser/views/preview_pane.py:695` — medium — Duration can remain that of the previous video indefinitely.**  
   Neither `set_video()` nor `stop()` resets `_duration`. If the first duration query for the new video fails during asynchronous loading, a positive duration from the previous file prevents the retry at line 695. No later timer or bus handler refreshes duration. **Trigger:** select a second video whose duration is not available within the first 500 ms, particularly over slower storage. The duration label, timeline-to-time conversion, and frame-step bounds use the previous video’s duration. **Fix:** reset per-file duration before loading and update it when asynchronous preroll/duration discovery completes, rather than relying only on two immediate queries.

4. **`src/gallerybrowser/views/preview_pane.py:939` and `:975` — medium — Video frames assume tightly packed RGB rows.**  
   Both appsink callbacks construct `QImage` with `bytesPerLine = width * 3`. GStreamer’s standard RGB row stride is rounded up to a four-byte boundary; buffers may additionally carry explicit video-layout metadata. **Trigger:** a video with width 854 produces default RGB rows of 2564 bytes, but this code advances by 2562, corrupting subsequent rows in both paused previews and playback. **Fix:** map through `GstVideo.VideoFrame`/`VideoInfo`, honoring actual plane offset and stride. See the [GStreamer raw-video layout specification](https://gstreamer.freedesktop.org/documentation/additional/design/mediatype-video-raw.html).

5. **`src/gallerybrowser/views/preview_pane.py:1647` — medium — Showing a video error leaves a dangling graphics-item reference.**  
   `_show_error()` clears the image scene directly, deleting its graphics items, but does not clear `ImagePreviewWidget._pixmap_item` or invalidate `_current_file`. **Trigger:** successfully preview an image, then select a video that cannot load—for example, with GStreamer unavailable—and click Fit. `reset_zoom()` passes the deleted pixmap item to `fitInView`, raising a wrapped-C++-object-deleted error. An outstanding image request can also overwrite the video error because its file remains current in the image widget. **Fix:** call the image widget’s `clear()` before adding error text.

6. **`src/gallerybrowser/views/info_pane.py:379` and `:421` — medium — Failed file-stat operations become uncaught metadata-rendering exceptions.**  
   Both metadata extractors initialize `"file_size": None` and retain that value when `stat()` fails. `metadata.get("file_size", 0)` does not replace an existing `None`; `format_file_size(None)` then raises `TypeError` at `core/metadata.py:181`. **Trigger:** a selected image/video disappears or becomes inaccessible before the worker obtains its metadata. Instead of showing the extractor’s error, the GUI slot raises during rendering. **Fix:** explicitly handle missing/`None` file sizes and render the extraction error or an unknown-size value.

7. **`src/gallerybrowser/views/info_pane.py:395` — medium — Unknown EXIF tag identifiers cause an uncaught Qt argument-type error.**  
   `MetadataExtractor` uses `TAGS.get(tag_id, tag_id)` at `core/metadata.py:68`, so tags unknown to Pillow retain integer keys. The pane passes those integers directly to `QTreeWidgetItem.setText`, which requires a string. **Trigger:** select an image containing an unknown or application-specific EXIF tag. **Fix:** convert tag identifiers to strings at the rendering boundary, or consistently return string keys from the extractor.

8. **`src/gallerybrowser/views/preview_pane.py:1420-1421` — medium — Leaving a sequence does not cancel its background loading.**  
   `SequencePreviewWidget.clear()` stops playback and empties the cache, but `SequencePlayer.stop()` only stops its timer and resets its index. It leaves the loader’s request generation and frame list intact. The loader therefore continues decoding and repopulating the cache; its signals are still accepted by the player and widget. **Trigger:** select a sequence, then switch to an image/video before preloading finishes. The hidden sequence continues disk/network reads and RAM allocation despite having been cleared. **Fix:** provide an explicit sequence-unload operation that invalidates pending loads and callbacks, rejects results from in-flight obsolete decodes, clears sequence state, and releases cached frames.

9. **`src/gallerybrowser/views/info_pane.py:456` and `src/gallerybrowser/views/preview_pane.py:1656` — high — Shutdown can destroy workers that are still running.**  
   Both cleanup methods request cooperative stop, wait only two seconds, and ignore whether the wait succeeded. Stop does not interrupt an operation already underway. Video metadata extraction explicitly allows a ten-second `ffprobe` call (`core/metadata.py:117`), and image I/O has no corresponding two-second bound. **Trigger:** close the application during slow metadata extraction or image loading. Cleanup can return while a child `QThread` is running, allowing destruction to reach Qt’s fatal “QThread: Destroyed while thread is still running” condition. **Fix:** keep worker ownership alive until `finished`, and cancel/terminate owned subprocess work where appropriate; do not proceed with thread destruction after an unsuccessful timed wait.


## Fullscreen viewer

Scope note: the current diff for this file changes only its executable bit. The findings below are **existing implementation defects from the requested whole-file audit**, not regressions introduced by that mode change. Review was read-only; no application or tests were run.

1. **`src/gallerybrowser/views/fullscreen_preview.py:648–666` — medium — Stop makes the current video unplayable.** The Stop button calls `stop()`, which sets the pipeline to `NULL` and discards it. Clicking Play or pressing Space afterward calls `play()`, which immediately returns because `_pipeline` is `None` (lines 608–610). No path is retained for reloading. **Trigger:** open a video, press Stop, then Play; playback cannot resume without navigating away and back or reopening the viewer. **Fix:** separate playback stop/reset from pipeline disposal; retain the loaded pipeline and rewind it for Stop, reserving disposal for navigation and closing.

2. **`src/gallerybrowser/views/fullscreen_preview.py:470–473,550–552,875–880` — medium — A newly opened video can permanently inherit the previous video’s duration.** `_duration` is initialized only in the constructor and is not reset by `stop()` or `load()`. If a second video’s initial duration query is not ready, the old positive duration remains.
